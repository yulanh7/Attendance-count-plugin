# 多堂签到（国语堂 / 粤语堂 / 英文堂）设计

日期：2026-11-12
状态：待确认

## 1. 背景与目的

现在的签到插件只服务国语堂。教会还有粤语堂，以及这次一起要做的英文堂。三个堂在**不同地点**聚会，会友都用**手机**签到，签到流程和国语堂完全一样。

要解决的问题：
- 每个堂有自己的签到页面，界面语言和团契名单也不同；
- 每个堂有自己的管理同工，**只能看、只能管自己堂的数据**；
- 会友可以自由去任何一个堂，也可能长期转到另一个堂。

## 2. 目标 / 非目标 / 反目标

**目标**
- 一套插件同时支持三个堂，签到和管理的逻辑都沿用现有国语堂的做法。
- 每个堂的签到页语言固定：国语堂用简体中文，粤语堂用繁体中文（香港用字），英文堂用英文。
- 各堂同工只能看到自己堂的数据，并且由服务器端强制执行，不能只靠"把页面藏起来"。
- 管理员能看到全部数据，并且可以按堂筛选。
- 上线后，国语堂现有的数据、页面和行为保持不变。

**非目标**
- 不做页面内的语言切换。
- 不做 WordPress 后台菜单 / 后台管理页面。所有管理（包括管理员）都在前台 shortcode 页面完成；现有被注释掉的 `admin_menu` 保持关闭。WordPress 后台只新增用户编辑页的「所属堂」字段。
- 不做跨教会、跨网站（多站点）的支持。
- 每个堂不单独设定签到日：三个堂都是星期天，继续沿用现有的 `ES_ATTENDANCE_DOW`。

**反目标（即使功能能用，也算失败的情况）**
- 某个堂的 Subscriber 能通过改网址、改接口参数等方式看到或修改其他堂的数据。
- 国语堂现有的出席记录、新来宾记录、会员状态在迁移后丢失或者统计结果变了。
- 签到流程对会友来说变得更复杂，比如普通签到时多出必须回答的问题。
- 出席率出现超过 100% 的情况。

## 3. 已确定的决策（来自用户）

### 3.1 堂与团契
| 堂 | 代号（我的决定） | 界面语言 | 团契 |
|---|---|---|---|
| 国语堂 | `mandarin` | 简体中文 | 但以理团契、真爱团团契、信望爱团契、平安喜乐祷告会、其他（沿用现有代号 `daniel` / `trueLove` / `faithHopeLove` / `peaceJoyPrayer` / `other`） |
| 粤语堂 | `cantonese` | 繁体中文（香港） | 五餅二魚團契、伊甸團契、長青團契、恩慈團契 |
| 英文堂 | `english` | 英文 | Timothy Youth Fellowship、Bereans Bible Study、Southside Bible Study、New Mercies Fellowship、Northside Connect Group |

- **我的决定**：粤语堂和英文堂也各加一个「其他 / Other」选项。原因是首次登记表单目前用隐藏字段把团契默认设成 `other`，新来宾登记时需要这个选项。
- 新团契的内部代号由开发者自己定，只要稳定、不和现有代号冲突就行。

### 3.2 页面与 shortcode
- **签到页**（公开）：每个堂一个页面，通过 shortcode 参数区分，比如 `[attendance_form congregation="cantonese"]`。不带参数时默认是 `mandarin`，这样国语堂现有页面不用改。
- **管理页**：都是**前台页面**，用户自己建页面、放 shortcode（`[attendance_dashboard]`、`[attendance_newcomers]` 等），再把链接发给同工。同工**不需要进入 WordPress 后台**。本文所说的「Dashboard」都是指 `[attendance_dashboard]` 这个前台页面。
  - 显示哪个堂的数据，由**登录账号**决定，不由页面决定。所以三个堂可以共用同一个页面，也可以各建一个页面，效果一样。
  - 管理员登录后打开同一个页面，会多出「按堂筛选」。

### 3.3 账号与权限
- 各堂的同工使用 **Subscriber** 账号。
- 在 WordPress 后台「用户」编辑页加一个「所属堂」字段（user meta），由管理员为每个同工账号指定一个堂。
- **管理员**（`manage_options`）：可以看全部堂，并且有「全部堂 / 国语堂 / 粤语堂 / 英文堂」筛选。
- **Subscriber**：只能看到和管理自己被指定的那个堂，包括 Dashboard、导出、出席详情、批量设置会员、新来宾名单、删除新来宾。所有相关的 AJAX 接口都必须在服务器端根据当前用户限定堂，忽略前端传来的堂参数。
- 没有被指定堂的 Subscriber：管理页显示「尚未指定所属堂，请联系管理员」，接口返回 403。
- 保留现有的 `ap_view_capability` / `ap_manage_capability` filter。

### 3.4 会友资料：全教会一份
- 一个电话号码对应一个人，不分堂。任何堂都可以用电话号码快速签到。
- 是否会员是全教会统一的。
- 每个人有一个**所属堂**（home congregation）：
  - 新人：在哪个堂首次登记，就属于哪个堂；
  - 现有的所有人：属于国语堂；
  - 所属堂决定「修改资料」时团契下拉框显示哪个堂的团契。

### 3.5 签到记录：记下实际签到的堂
- 每条出席记录都存一个「堂」字段，记录**实际签到的堂**，不是所属堂。
- **一个人每天只有一条签到记录，不分堂**（保留现有的唯一键 `(attendance_id, date_attended)`），所以出席率不可能超过 100%。
- **同一天在第二个堂签到时，让他自己选**：
  > 您今天已在**國語堂**簽到。要改為在**粵語堂**簽到嗎？
  > 〔改為粵語堂〕　〔保留國語堂〕
  - 保留：什么都不改。
  - 改为：把今天那条签到记录的「堂」改成新的堂（仍然只有一条）。新来宾记录一起处理：
    - 如果这个人今天是**全新登记**（`first_attendance_date` = 今天）：所属堂改成新的堂，今天的新来宾记录（如果有）也移到新的堂。
    - 否则：如果旧的堂今天有他的新来宾记录（是今天"第一次去旧堂"时自动加的），删掉这条记录。
    - 移过去之后，按新的堂重新套用 3.7 的规则（第一次在新堂 → 自动加入新堂的新来宾名单；如果新堂不是他的所属堂，出转堂提示）。
  - 在同一个堂重复签到，仍然提示「今天已经签到过了」。
- 现有的所有出席记录、新来宾记录都归到国语堂。

### 3.6 Dashboard 与出席率
- 各堂只统计**在本堂签到的记录**。
- 出席率 = 区间内在所选范围（本堂，或管理员选的「全部堂」）的签到次数 ÷ 区间内的主日数（从这个人第一次出席开始算，沿用现有的算法）。
  - 举例：4 个主日里，去了 2 次国语堂、2 次粤语堂。国语堂看到 50%，粤语堂看到 50%，管理员选「全部堂」看到 100%。
- 管理员的表格多一列「堂」。选「全部堂」时，这一列显示按堂分布的次数（比如「国语 3、粤语 1」）。Subscriber 看不到这一列，也没有堂的筛选。
- CSV 导出和表格一致：管理员的导出包含「堂」列，Subscriber 的不包含。
- 「≥ 50%」、「会员 / 非会员」等现有筛选，都在所选堂的范围内生效。

### 3.7 第一次去别的堂（核心新流程）
触发条件：某人在某个堂签到成功，而且**这是他第一次在这个堂签到**（这个堂之前没有他的出席记录）。

1. **自动加入这个堂的新来宾名单**。如果他以前在别的堂出席过，名单卡片上标注「曾在〔国语堂〕出席」。同工可以用现有的「移出新来宾名单」把他移出。
2. **如果这个堂不是他的所属堂**，签到成功后给一个提示（用这个堂的界面语言）：
   > ✅ 簽到成功！
   > 您目前登記在**國語堂**。以後會固定在**粵語堂**聚會嗎？如果是，請選擇您的團契。
   > 〔是，轉到粵語堂〕　〔不用，只是這次〕
   - 选「不用」：结束，什么都不改。
   - 选「是」：进入修改资料页面，资料已经载入，所属堂已经切换到这个堂，团契下拉框换成这个堂的团契，而且**必须重新选一个团契才能保存**。保存后转堂才生效；如果他中途取消，所属堂不变。
3. **同一个人在同一个堂只提示一次**。因为触发条件是"第一次在这个堂签到"，第二次来就不会再提示，不需要额外记录。
4. 签到本身不能因为这个提示变慢或者失败：提示出现在签到**成功之后**，会友可以直接关掉。

### 3.8 修改资料
- 加一个「所属堂」下拉框，会友可以随时自己转堂。
- 切换所属堂后，团契下拉框换成新堂的团契，并且要求重新选择团契。
- 如果他原来的团契属于别的堂，下拉框里仍然显示原来的团契（标明属于哪个堂），避免误改。

### 3.9 首次登记
- 沿用现有流程（包括「是否是新来宾」勾选框，以及"号码已存在时转去快速签到"的逻辑）。
- 新人的所属堂设为当前签到页的堂；新来宾记录也记在这个堂。
- 如果号码已经存在、转去快速签到，适用 3.7 的规则。
- **我的决定**：全新号码的首次登记，是否进入新来宾名单**仍然由勾选框决定**，3.7 的"自动加入"只适用于**已经在系统里的人**第一次去别的堂。原因是新堂刚上线时，会有很多老会友第一次在系统里登记，他们取消勾选就不会被当成新来宾。
- 签到成功的提示可以带上欢迎语，比如「歡迎您第一次來到粵語堂！」（第一次在这个堂签到时显示）。

### 3.10 批量设置会员的范围
- **我的决定**：Subscriber 只能对**在自己堂有过出席记录的人**设置会员状态，服务器端要检查。会员状态本身是全教会统一的（见 3.4），这一条只是防止他们修改和本堂无关的人。

## 4. 现有数据迁移
- 给人员表加「所属堂」，给出席表和新来宾表加「堂」字段；所有现有数据填 `mandarin`。
- 迁移通过现有的 `Install::maybe_upgrade()`（`SCHEMA_VERSION`）完成，要求幂等，可以重复执行。
- 迁移完成后，国语堂的 Dashboard 结果要和迁移前完全一致。上线前要用本地真实数据（约 295 人、5347 条出席记录）对比验证。

## 5. 界面文字
- 签到表单、提示信息、管理页面上的所有文字，都要有三种语言版本。语言由「堂」决定：
  - 签到页：看 shortcode 参数；
  - 管理页：看登录账号的所属堂（粤语堂同工看繁体，英文堂同工看英文）；
  - 管理员：一律用中文（简体），不管筛选的是哪个堂。
- 现在 `assets/js/main.js` 里写死了很多简体中文提示（包括 `confirm()` 对话框）。这些要改成由 PHP 按堂传入的文字（比如通过 `wp_localize_script`）。
- 用什么方式做翻译（PHP 字符串表，还是 WordPress 的 gettext/.po）由开发者决定。**我的建议**：用简单的 PHP 字符串表，按堂代号分组，方便教会同工以后自己改字。
- 日期继续用 `d/m/Y` 格式。

## 6. 留给开发者决定的事
- 数据库字段名、索引、新来宾表的唯一键怎么调整（现有新来宾表可能已有同一个人多条记录，迁移时不能报错）。
- 新团契的内部代号。
- 「曾在〔X堂〕出席」是写入时存下来，还是查询时实时计算。
- `[attendance_first_timers]`（按全教会首次出席日期统计）在多堂下怎么限定范围：建议按这个人第一条出席记录所在的堂来归属。
- 缓存键要包含堂和当前用户的权限范围，避免不同堂的同工看到对方的缓存结果。
- 「出席详情」弹窗里，管理员可以看到每次出席所在的堂。
- 管理员的新来宾名单页面也要有「全部堂 / 各堂」筛选，卡片上标明属于哪个堂。
- 签到页 Logo 和标题是否按堂区分（如果没有特别要求，沿用现在的 Logo，标题换成对应语言）。
